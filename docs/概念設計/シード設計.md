# シード設計

- version: 0.1
- 作成日: 2026-05-10

---

## 基本方針

**マスターシード1つで世界全体を再現する（世界単位の再現性）**

同じマスターシードを使えば、世界の地名・勢力・全キャラクターの素質・クエストの内容が
すべて同じように生成される。プレイヤーはシードを共有することで
「同じ世界・同じキャラクター」を語り合える。

---

## シードの派生構造

マスターシードを起点に、用途ごとにシードを派生させる。
用途が独立しているため、一方の乱数消費が他方に影響しない。

```
マスターシード
    ├─ 世界生成シード   = マスターシード
    ├─ キャラクターシード = マスターシード + キャラクターID
    ├─ クエストシード   = マスターシード + 日付 + クエストカウンター
    └─ イベントシード   = マスターシード + イベントID
```

---

## シードで生成できるもの・できないもの

| 項目 | シードで生成 | セーブデータに保存 |
|---|---|---|
| 世界の地名・初期勢力配置 | ◎ | — |
| キャラクターの素質（能力値のベース） | ◎ | — |
| キャラクターの初期割り振りポイント量 | ◎ | — |
| プレイヤーによる初期割り振りの配分 | — | ◎ |
| クエストの内容・難易度 | ◎ | — |
| クエストの結果（成功/失敗） | — | ◎（履歴として） |
| キャラクターの成長・変化 | — | ◎ |
| 勢力バランスの変化 | — | ◎ |

---

## 乱数呼び出しの窓口設計

コード全体で乱数を直接呼び出すことを禁止し、必ず窓口関数を経由する。
窓口の内部実装（仮実装→シード付き実装）を差し替えるだけで全体に反映される。

```js
// 窓口関数のインターフェース（実装はSprint 4-3）
getRandom(purpose, id)
// purpose: "character" | "quest" | "event" など用途
// id: キャラクターIDやクエストIDなど一意な識別子
// return: 0以上1未満の浮動小数点数
```

**仮実装（Sprint 1-3〜Sprint 4-2）**
```js
getRandom(purpose, id) {
    return Math.random();
}
```

**本番実装（Sprint 4-3）**
```js
getRandom(purpose, id) {
    const seed = deriveSeed(masterSeed, purpose, id);
    return seededRandom(seed);
}
```

## キャラクター生成におけるシードの役割

ウィザードリィ方式を採用する。

1. シードからキャラクターの「素質」（能力値のベース・ボーナスポイントの総量）を生成
2. プレイヤーがボーナスポイントを能力値に割り振る
3. 割り振り結果はシードで再現できないためセーブデータに保存する

```
シード → 素質（ベース値・ボーナスポイント量）
              ↓
         プレイヤーが割り振り
              ↓
         初期パラメータ確定 → セーブデータへ
```
